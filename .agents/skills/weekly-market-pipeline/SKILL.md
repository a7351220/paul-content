# 六站內容流水線

本 skill 是流程與交接的唯一入口；敘事及聲音只依 [共用框架](../market-video-story/references/story-framework.md)，GitHub 同步只依 [AGENTS.md](../../../AGENTS.md)。生產單位是一段完整故事，不是一頁。從目前進度接續，只做當次授權範圍；專責 skill 做完即交下一個需要的階段，不回本入口反覆分派。

## 六站：輸入 → 工作 → 輸出

| 站 | 輸入 | 工作與負責者 | 輸出 |
|---|---|---|---|
| 1 接續 | 本次要求、最新人工稿、相關舊期及同集紀錄 | 確認正式稿、目前人工編輯位置、授權輸出與截止時間；按共用框架取回聲音及觀眾已知背景 | 同一份工作紀錄的簡短任務範圍，不另造企劃 |
| 2 取證 | 題目、已有材料、具體缺口 | [研究](../weekly-market-research/SKILL.md) 核對主張、來源、時間與計算；只補不足，不重跑完成的搜尋 | 同集研究紀錄中的可用證據與未知 |
| 3 完整敘事 | 證據、前文理解、認可聲音 | [寫作](../weekly-market-writing/SKILL.md) 先把主題連續講完，再接全片；不先做格子逐頁填字 | 一份連續口播稿；只要大綱時交內容走向，不提前寫全文 |
| 4 通讀分頁 | 連續故事或已核定現稿 | 寫作先通讀刪重、補前因，再按證據及推理轉折分頁；依研究紀錄核對數字與必要歸屬 | 可錄製的分頁正式稿；大綱任務到指定大綱即止 |
| 5 製作 | 已確認稿件版本、認可版型 | [製作](../market-video-story/SKILL.md) 產出授權的視覺、PPTX／Canva，不另改口白 | 對應同一版正式稿的製作物 |
| 6 同步並留下記憶 | 正式稿、人工差異、已製作交付物 | 採用的文字回寫唯一正式稿並讀回；依製作規則讀回人工改動，只同步已授權交付物及受影響部分；依 AGENTS 保存到正確 repo | 明列版本與已／未同步範圍，並更新同集短紀錄 |

## 最少關卡與修改邊界

題目未定才請使用者確認選題與範圍，已指定就跳過。需要人工審稿時集中看完整口播，不每題、每頁或每站再批准；已授權直接交付就接續。沿用認可版型直接製作，新方向、實質衝突或超出授權才停下確認。

只改數字：研究核對新值、時間及公式，寫作只修因此失效的解讀。只潤一段：保留其他人工文字，檢查必要銜接。改結構：才擴大檢查頁序與引用。製作與同步只驗受影響項目；首次交付保留必要完整核對。沒有新差異就停止，不把每個修改變成全流程重跑。

遇缺口只交具體主張／數字、來源期間及所需資料給負責階段，取得後回原工作；未解就報缺少什麼並繼續獨立部分，不反覆轉交。同一份稿與研究紀錄往下走，不另複製多套大綱、核對表或記憶庫。

## 一份稿源與同集記憶

在既有同集工作紀錄記清正式稿位置／版本、目前人工編輯位置、截止時間、鎖定頁序／標題及授權交付物。Google Doc 或 Canva 有人工改動時，先讀回最新內容與差異，再更新正式稿；本地新舊稿、線上稿不能各自繼續生產。缺內部欄位不構成重做理由，疑似版本衝突不以舊檔覆蓋。

收尾只留三項可追溯記憶：①本集已講成立的理解；②尚未解答／下次值得追的問題；③使用者認可或刪除的聲音例子。附對應稿件版本／頁段，放在同集既有紀錄，不新增平行資料庫。未有明確回饋不捏造偏好，刪句也不一律推論成永久禁用。下次只讀相關紀錄並回原稿核對；歷史結論不是當期事實。不要把私人互動、聯絡資訊或內部工具資料寫入公開紀錄。
