Abstract
Significant efforts are currently being directed toward the implementation of large-scale quantum information processors, but realizing useful quantum advantage also requires the development of efficient quantum algorithms.
While for many practical problems the dominant resource costs are associated with
a small set of computational primitives,
optimizing them in the quantum setting presents unique challenges, including a
reversibility constraint absent from ordinary classical computation.
Here we introduce an evolutionary framework in which large language models (LLMs) propose circuit designs and an independent evaluator verifies and scores them.
We apply this framework to tasks spanning numerical computation, chemistry, optimization, quantum simulation, and number theory.
In seven of the eight tasks, the discovered circuits significantly reduce both Toffoli and qubit counts relative to the state of the art.
In the eighth, the search discovers a new reversible architecture for prime-field modular inversion.
By handling reversibility differently, the architecture makes divsteps—a classical algorithm previously impractical for reversible integer arithmetic—viable
and substantially improves the Toffoli–qubit trade-off for modular inversion.
These results open the door for evaluator-guided LLM co-design of
new algorithmic structures for quantum computation.
Computational primitives based on classical function evaluation play a central
role in a wide range of quantum algorithms. Such primitives include decoding routines for
optimization [1], numerical functions for quantum
simulation [2], arithmetic
routines for number theory [3], and quantum read-only memory
(QROM), which coherently loads classically specified data into quantum
registers [4]. To operate on quantum data, these
functions must be compiled into circuits that can be executed coherently on quantum hardware. This imposes
two constraints absent from ordinary classical programs. First, because the
input may be in superposition, the circuit cannot inspect an intermediate
value and select an ordinary classical control-flow path. Data-dependent
behavior is instead expressed through controlled operations within a
fixed gate sequence, so every branch contributes to the circuit’s cost even if
it applies only to some inputs. Second, the computation must be reversible:
intermediate information cannot simply be overwritten or discarded. Temporary
values must eventually be uncomputed, returning their qubits to their initial
state and preventing residual information from remaining entangled with the
output. Until they are uncomputed, these values occupy additional qubits. At the same time, when bounded error is permitted, machinery needed only for rare or atypical
inputs can sometimes be omitted, reducing resource requirements while keeping
the failure probability controlled.
Efficient coherent compilation is of major practical importance, and recent reductions in resource requirements have come
from coordinated changes to arithmetic algorithms, data representations, and
their reversible
implementation [5, 6]. Such redesigns
are difficult for general quantum circuits because directly
testing correctness can require exponentially expensive classical simulation or fully operational large-scale quantum processors. Automated circuit
optimizers therefore typically preserve correctness by restricting the search
to predefined equivalence-preserving rewrites [7],
limiting them to variations of a fixed design.
Here we introduce a framework that pairs large language model (LLM) proposals with an independent evaluator that verifies and scores each candidate.
We focus on a class of quantum circuits that compute a classical function ff: for an arbitrary input
|ψ⟩=∑x,yαx,y​|x⟩​|y⟩\ket{\psi}=\sum_{x,y}\alpha_{x,y}\ket{x}\ket{y}, the circuit
must act as |ψ⟩⟼∑x,yαx,y​|x⟩​|y⊕f⁡(x)⟩\ket{\psi}\longmapsto\sum_{x,y}\alpha_{x,y}\ket{x}\ket{y\oplus f(x)}, where |x⟩\ket{x} and |y⟩\ket{y} are computational-basis
states of the input and output registers, respectively. By linearity, this coherent action is
correct if the circuit performs the required map on every computational-basis
input: |x⟩​|y⟩⟼|x⟩​|y⊕f⁡(x)⟩\ket{x}\ket{y}\longmapsto\ket{x}\ket{y\oplus f(x)}.
This basis-state reduction makes candidate circuits amenable to programmatic
evaluation, since every
allowed operation maps a computational-basis state to another
computational-basis state, possibly changing its phase, but never creating a
superposition [8]. The action of a candidate on any
chosen input can therefore be simulated by tracking a bit string and its phase,
rather than 2n2^{n} amplitudes. Resource accounting is also simple: we use the
Toffoli count TT and the peak qubit count QQ, and rank circuits by their product, the T​QTQ-cost.
Together, these properties let us
build an efficient, programmatic evaluator that checks the correctness and resource cost of any candidate circuit design.

Each search begins from a hand-written task specification and a blank
program; the specification states the required circuit behavior but provides
no implementation guidance. The LLM proposes a candidate and iteratively revises
it using evaluator feedback (Figure 1(a)). Previous work
represents candidates as sequences of gates or predefined circuit
blocks [9, 10], which can obscure
the algorithmic structure of the circuit. Our framework instead
lets the LLM propose and revise candidates through a high-level Python interface,
where reusable functions and ordinary programming constructs make that structure
explicit. This allows a single conceptual change to reorganize operations
throughout the circuit, while the evaluator tests its consequences for
correctness and resource cost. However, purely iterative refinement of a
single candidate can remain tied to the architecture from
which it began, resulting in convergence to local (but not necessarily global) optima. We therefore start with an ideation stage in which the LLM is prompted to propose several distinct algorithm families, each
representing a different approach to the problem. Circuits within each family
are optimized independently in parallel, allowing the search to explore different strategies rather than
only variations of one design. Well-performing candidates are periodically shared
between families so that an idea discovered in one approach can inform
another.
Across eight diverse compilation tasks, the discovered circuits repeatedly
exhibit three common principles of algorithm–circuit co-design. These
principles address the features of
coherent compilation described above: expressing data-dependent control flow, making intermediate computations reversible
without retaining their entire history, and using a failure budget to remove circuit resources devoted to atypical cases (see Figure 1).
Design principles
One recurring principle in the circuits discovered by the search is to replace
conditional arithmetic with conditional routing. A naïve coherent
translation of a casewise classical algorithm includes a separately controlled
arithmetic block for every branch. The discovered circuits
instead use a representation in which the branches differ primarily in which
values occupy particular computational roles. Relatively cheap controlled swaps then
route the appropriate values into those roles, one unconditional arithmetic
path performs the expensive work, and further routing places the results in
their required registers. In this sense, where a classical program routes
execution to the selected operation, the coherent circuit routes the selected
data through a shared operation. The idea resembles bucket-brigade quantum random-access memory (QRAM) [11].

zz, together with a control qubit bb. Suppose that we wish to perform

More generally, conditional routing requires canonicalizing
branch-dependent states into a representation on which the same expensive
computation applies. Schematically, when the branch can be expressed as Ub=Rb−1​K​RbU_{b}=R_{b}^{-1}KR_{b}, the circuit need only control the inexpensive routing transformation RbR_{b};
the expensive kernel KK appears once and need not be controlled. Finding such
a decomposition typically takes more than recognizing identical arithmetic in two
branches: it exploits an equivalence
in the required output so that apparently different updates become instances
of the same computation. The difficulty lies less in the
routing circuit than in determining which
branch-dependent differences matter and which can be absorbed into a shared
representation.
Reversibility creates a second challenge: reversing a conditional update
requires knowing which branch was taken during the forward computation. A
naïve implementation records each decision in a history stack whose
size grows with the number of updates. But the branch decisions need not always
be stored explicitly: different branches may leave distinguishable patterns in
registers that remain available during uncomputation. As illustrated in Figure 1(c), the circuit can recover
the branch bit from such a pattern, use it to select the appropriate inverse
update, and then clear the recovered bit, so the register contents serve as an
inexpensive record of the branch decisions. For example, suppose we have a register gg that begins at g0=0g_{0}=0. In round jj, conditioned on some branch bit bjb_{j}, we add 2j2^{j}, so that
gj+1=gj+bj​2j.g_{j+1}=g_{j}+b_{j}2^{j}.

separate history stack. In general, finding such a decoder requires the forward algorithm, its data
representation, and its uncomputation procedure to be designed together.
Viewed locally, an update may be ambiguous, since either branch can appear
to admit a valid predecessor. The ambiguity can disappear once the circuit is
restricted to states reachable from the prescribed initialization, where a
relation across the registers can distinguish histories that no single
register can.
The third principle exploits the small but finite failure probability permitted
by most quantum algorithms. Turning this failure budget into resource
savings, however, is not automatic. One must first identify the rare
inputs that determine worst-case resource requirements. Unlike a
classical program, a quantum circuit must contain the gates and ancillas
required by every supported path. A rare input can therefore determine
the circuit’s Toffoli count or peak qubit count. Yet identifying such inputs is
not enough: the circuitry supporting them may not be separable from the
computation on typical inputs. The co-design task is to reorganize the
computation so that the additional resources required by rare inputs are
localized—for example, to extra iterations, stack entries, or arithmetic
lanes. Those components can then be omitted while confining failure to the
low-probability inputs that require them
(Figure 1(d)). In what follows we show how these design principles result in significantly improved algorithmic circuits across a wide variety of quantum tasks.
Reversible syndrome decoding for DQI
Decoded quantum interferometry (DQI) is a quantum algorithm that turns certain
optimization problems into decoding problems for classical error-correcting
codes, using quantum interference to favor better solutions. A central
application is optimal polynomial intersection (OPI), a form of polynomial
fitting over finite fields for which DQI offers a superpolynomial speedup over
known classical algorithms. DQI achieves this by using a Reed–Solomon decoder
as a subroutine within the quantum computation [1]. The decoder identifies the positions and values of errors from a collection
of algebraic checks called syndromes. DQI requires this decoding to run
coherently on a superposition of inputs, making the reversible decoder a
dominant resource cost. Khattar et al. [13] compiled DQI circuits
for OPI over binary extension fields using reversible Reed–Solomon decoders
based on the extended Euclidean algorithm.
We study their primary Reed–Solomon instance, in which 70 syndrome values
uniquely determine an error pattern containing at most 35 errors. Our search
framework discovered a circuit that replaces their synchronized Euclidean
solve with the Berlekamp–Massey (BM) recurrence. BM substantially reduces the
arithmetic cost, but its updates overwrite intermediate values that a
naïve reversible implementation would retain in a large history
stack. The discovered circuit preserves BM’s arithmetic advantage while
avoiding most of this storage (Figure 2).

Reversible modular inversion
Modular inversion is the task of finding xx such that w​x≡1(modp)wx\equiv 1\pmod{p},
given a nonzero input ww and a prime pp. It is a central arithmetic subroutine
in a range of quantum algorithms [14, 3].
A standard way to compute the inverse is through the extended Euclidean algorithm.
Euclidean algorithms repeatedly simplify a pair of integers while preserving
their greatest common divisor. By tracking how this divisor is expressed in
terms of the original inputs, they also recover coefficients α,β\alpha,\beta satisfying
α​p+β​w=1\alpha p+\beta w=1, so β\beta is the inverse of ww modulo pp.
Divsteps is a variant of the Euclidean algorithm that replaces division with
conditional additions, subtractions, and halving [15].
Starting from f=pf=p and g=wg=w, the goal is to reduce the pair to f=±1f=\pm 1 and
g=0g=0 while preserving their greatest common divisor. The basic strategy is to
hold the odd integer ff fixed while reducing gg: if gg is even, it can be
halved directly; if gg is odd, adding or subtracting ff first makes it even.
These operations preserve the greatest common divisor because ff is odd. Holding ff
fixed indefinitely, however, would leave only one integer being reduced, so
the algorithm must periodically swap their roles. A small signed counter
zz schedules these swaps without ever comparing ff and gg: it roughly
tracks how many more bits ff has than gg, so a swap occurs
once gg is likely the smaller of the two. This allows

probability. We use this failure budget to exclude rare, unusually demanding
inputs through two resource limits: a fixed history-stack size and a fixed
window of supported stopping times. The history-stack limit builds on the decoding trade-off. With
jstore=5j_{\mathrm{store}}=5, only 12.4%12.4\% of ambiguous decisions are written to the stack
(Figure 3(a)). On average, the required stack size is 21 history qubits, but it can reach 263 in the worst
case. We instead reserve 60 and allow the circuit to fail on rare
inputs for which the stack overflows. Such overflows occur with probability
2.4×10−62.4\times 10^{-6} per inversion (Figure 3(b)), saving 203 history qubits relative
to the worst case. The stopping-time limit addresses a separate cost. A fixed quantum circuit
must schedule enough steps for every input it supports. Although 590 divsteps
suffice even in the worst case, stopping times are concentrated in a much
narrower range (Figure 3(b)). The discovered circuit therefore
schedules 533 steps and tests for termination only from step 499 onward;
inputs that terminate outside this window are allowed to fail.
Branch decoding and bounded resource allocation thus make divsteps
practical for reversible modular inversion. A complete benchmark circuit built on this inversion
(SI II) uses 4.0 million Toffolis and 935 qubits.

A recurring source of these gains is the recovery of classical algorithmic
efficiency under the constraints of quantum computation. In a naïve reversible
implementation, coherent control and cleanup can introduce enough overhead to
obscure the advantages of an efficient classical method. Our Berlekamp–Massey
and divstep constructions show how jointly choosing the algorithm,
representation, and uncomputation can recover those advantages. These results suggest that some
apparent costs of quantum arithmetic reflect limitations of existing reversible
constructions rather than of the algorithms themselves.
Finding such constructions requires reasoning about choices whose benefits
depend on one another. An arithmetic saving may become useful only after the
associated control and uncomputation costs have also been reduced. A candidate
design must therefore be carried through several
unresolved mathematical and
implementation problems before its resource advantage becomes apparent.
The framework is bounded by the choices that define each
task. One is the objective that ranks circuits: we use the T​QTQ-cost
for a uniform comparison, but other objectives are equally reasonable. In practice, the relative importance of qubit count, depth, routing, and measurements
depends on details such as hardware constraints, decoder performance, and error-correction architecture. The scoring function can be
replaced with a hardware-appropriate combination of these resources, but
determining that objective remains a matter of application and hardware judgment. The circuit interface defines a second boundary. Here, the required
transformation is specified in a fixed computational basis, excluding
optimizations whose advantage comes from changing the encoding itself. For
example, coset representations can make modular addition cheaper by encoding
each residue as a superposition of congruent integers, which avoids conventional
comparisons and corrections at the cost of an exponentially small
error [17, 18], but such encodings lie outside
the present framework. More generally, the task boundary, input distribution, data representations, and accuracy target make a
search well posed while also encoding assumptions about how the circuit is
embedded in a larger algorithm (in particular, which states it receives and how its
outputs are consumed).
The same choices that bound the search also make reliable programmatic feedback
possible: they specify what each candidate must preserve and which resource
trade-offs the evaluator should reward. Within these boundaries, our results
show that evaluator-guided LLM search can go beyond refining a fixed circuit
to uncover new reversible algorithms and representations. Related
approaches have produced new algorithms in combinatorics and linear
algebra [19, 20]. These observations suggest a
practical criterion for extending the approach: wherever a problem admits a
sufficiently expressive task interface and its correctness and resource costs can
be evaluated cheaply enough to sustain many rounds of search, the same evaluator-guided search
may provide a route to new algorithms.
These results, together with
related progress in reinforcement learning and LLM-guided discovery of quantum
error-correcting codes and encoding
circuits [21, 22, 23], create an opportunity for end-to-end
co-design of fault-tolerant computation. Choices that are usually made
separately—the algorithm and its logical circuit, the error-correcting code
and its method for universal logic, the supply of magic states, and the physical
execution architecture—strongly determine one another’s costs. A programmatic evaluator that propagates logical errors, resource
demand, and hardware requirements across these layers could allow an LLM search to
redesign them together, potentially discovering fault-tolerant algorithms and architectures
that cannot be found by optimizing each layer in isolation.

Methods
A classical function cannot generally be applied directly within a quantum
algorithm, because quantum evolution must be reversible. Instead, a function
ff is embedded in a reversible map |x⟩​|y⟩⟼|x⟩​|y⊕f⁡(x)⟩\ket{x}\ket{y}\longmapsto\ket{x}\ket{y\oplus f(x)}.
A natural model for these subroutines is the kickmix circuit model of
Babbush et al. [8], which augments reversible classical computation
with measurement-based uncomputation (MBU) and diagonal sign gates.
Despite these additional operations, kickmix circuits remain efficiently
classically simulable. This allows candidate circuits to be tested for their
action on coherent quantum superpositions, providing the reliable correctness
signal needed for evolutionary search.
Circuits that implement the same specification can have very different time
and space requirements. We use Toffoli count and peak qubit count as
proxies for these costs. Toffoli gates require expensive
non-Clifford resources, so their count tracks a
large part of the logical work and often the
runtime [24, 25]. The peak qubit count measures the
data and ancillas that must coexist during execution and therefore
approximates the required logical processor
footprint [26]. The two resources also typically trade against
each other: additional ancillas can avoid recomputation, while recycling
ancillas can reduce space at the cost of additional gates. We multiply these
quantities to obtain the T​QTQ-cost, which provides a single objective for
comparing such designs.
Together, the correctness tests and T​QTQ-cost define a constrained
optimization problem over circuit-generating programs. Motivated by recent
advances in coding and reasoning agents and LLM-guided algorithmic discovery,
we use an LLM to propose coordinated, task-specific redesigns within an
evolutionary search [27, 28, 20].
Circuit model and validity
A compilation task specifies a reversible action on computational-basis
states: a permutation π\pi and, when needed, a Boolean phase gg. A circuit
may use aa ancilla qubits, but must return them to zero:
V​|x⟩​|0a⟩=(−1)g⁡(x)​|π⁡(x)⟩​|0a⟩.V\ket{x}\ket{0^{a}}=(-1)^{g(x)}\ket{\pi(x)}\ket{0^{a}}.
(10)
Every ancilla must return to |0⟩\ket{0} because
quantum operations must be unitary, and thus reversible. For a
numerical approximation, the required output relation may instead specify an
error bound; interface preservation, phase correctness, and ancilla uncomputation
remain exact. We separately allow some circuits to fail on a bounded fraction
of inputs drawn from a stated distribution; this fraction is the failure budget. Following Babbush et al. [8], the kickmix model permits three
classes of operation:
1.
classical reversible gates: XX, CNOT, Toffoli, and swap;
2.
diagonal sign gates: ZZ, CZ, CCZ, and global sign flips; and
3.
destructive XX-basis measurements.
Before any measurement, the evolution of a computational-basis input is
simple. Reversible gates update its stored bit string, while
diagonal gates update only its sign, so the state remains of the form
(−1)ϕ​|x⟩(-1)^{\phi}\ket{x}. A classical simulator therefore need only track the
current bits xx and the sign ϕ\phi, rather than a full state vector. The operations apply phase
kickback while mixing basis states, giving kickmix its
name.
To illustrate why uncomputation is costly, consider a temporary AND. A
Toffoli computes t=u​vt=uv into an ancilla. After tt has been used, applying the
same Toffoli again returns that qubit to zero:

uniformly random outcome rr and releases the ancilla, which can be restored
to |0⟩\ket{0}:

Validation and statistical guarantees
The circuits are ultimately applied to coherent superpositions, whereas the
evaluator follows one computational-basis trajectory at a time. Each test
must therefore capture enough information to determine the trajectory’s
coherent action. For a basis input xx and measurement record mm, the
evaluator checks that the output matches the target, required inputs are
unchanged, every ancilla has returned to |0⟩\ket{0}, and the phase agrees with
the target exactly. These checks compare the complete final state rather than
only its classical output. An ancilla that retains input-dependent information
can become entangled with the logical registers, while an incorrect sign can
alter subsequent interference without changing any output bit. Resetting or tracing out a dirty
ancilla is therefore not a substitute for uncomputing it.
If every pair (x,m)(x,m) passes these tests, the measurement record factors from
the logical output, and linearity extends agreement on every trajectory to any
coherent input. For large input domains, however, the evaluator samples these
trajectories rather than checking them all.

Cost model and scoring
We define the T​QTQ-cost of a circuit by
T​Q=Toffoli count×peak qubit count,TQ=\text{Toffoli count}\times\text{peak qubit count},
(22)
where TT counts Toffoli and CCZ gates equally and QQ is the largest number of logical
qubits allocated at once.
We weight space and time equally in this cost function for simplicity. In
practice, their relative importance depends on the hardware and application.
When qubits are scarce, for example, a cost of the form
(qubit count)κ×Toffoli count(\text{qubit count})^{\kappa}\times\text{Toffoli count} with
κ>1\kappa>1 may be more appropriate; resource estimates for factoring
have used κ\kappa between 1 and
3 [30, 6]. Either TT or QQ can also be replaced with other measures of time or space.
In particular, when there is limited magic-state-factory throughput (as is typically the case), runtime is bottlenecked by the Toffoli count, motivating its widespread use as a time proxy [24, 25]. However, with
enough factories to supply magic states in parallel, Toffoli depth rather than
Toffoli count limits runtime. Similarly, for architectures with cheap cold storage for inactive qubits [31], QQ can be replaced by active
volume [32], which counts only the qubits
participating in logical operations.
The search is not tied to the specific form of the T​QTQ-cost: it can run with any
computable objective. A later case study
illustrates the available trade-offs: the modular-inversion search
(SI II) produces a family of circuits along a
Toffoli–qubit frontier (SI II.1), and an
objective that weights qubit count more heavily selects a lower-qubit member
of that family.
Evolutionary search
We encode each candidate as Python code that constructs a circuit. Functions,
loops, and named registers preserve the organization of the computation,
allowing the LLM to reason about arithmetic subroutines and their composition
without reconstructing that structure from a flattened gate sequence. For
example, changing a shared arithmetic routine changes every place where it is
used, while reorganizing calls to that routine can change when intermediate
values are computed, retained, and uncomputed. The representation thus makes
coordinated changes expressible as revisions to the underlying algorithm.
We search over these circuit-generating programs with
OpenEvolve [33], using Claude
Mythos 5 [28] to propose architectures and program
rewrites. Each of the eight searches uses a fixed, hand-written task specification, and all
share the same generic circuit-building interface. During ideation, the LLM receives
only the specification, circuit model, and correctness criteria, and proposes several
distinct circuit architectures. The LLM has no access to the
evaluator beyond the feedback returned
after each submission. Starting from a blank program, it chooses the algorithm,
representation, and circuit structure and produces the discovered circuits
without substantive human intervention.
Each architecture proposed during ideation founds a separate family of
candidate programs. Later iterations improve descendants of the first working
implementation. Keeping the families separate at first gives each approach
time to mature, even if its earliest circuits are less efficient than those
based on another approach. Periodically, leading programs are shared across
families, allowing successful ideas from different approaches to combine.
The search retains candidate programs and their evaluation results, tracking
which family each belongs to and which earlier program it was derived from.
It also saves feedback on failures and short notes in which the LLM records
useful insights. These programs, results, and notes carry information between
iterations; the sessions do not share a continuously growing conversation.
Each iteration starts a new LLM agent session with the task specification, a
parent program to improve, and its evaluation feedback. The agent also
receives alternative programs from the archive and their resource costs, brief
summaries of earlier attempts, and recorded insights where available. This
context is limited; the agent never sees the complete search history. Within
the session, it may rewrite the program, run drafts on test inputs, query a
classical oracle for the required function on chosen inputs, and use the
results to revise its design. It may also delegate focused subtasks to subagents.
The iteration ends with submission of a revised
program. The evaluator rejects a circuit that does not
meet the task specification; a valid one is scored by its T​QTQ-cost and
considered for retention in its family. Thus the LLM is free to propose
broad changes without having to judge their correctness: the evaluator
supplies an independent test of every completed design.
shows the ideation and rewrite calls and a concrete
feedback-and-repair cycle for a small finite-field inversion task.
To decide which valid candidates remain available within each family, the
search retains circuits with different trade-offs between Toffoli count and
qubit count. We implement this selection with
MAP-Elites [34], which divides the (T,Q)(T,Q) resource plane
into cells and keeps the circuit with the lowest T​QTQ-cost in each cell. A
space-efficient circuit can therefore remain available for later development
even when its higher Toffoli count gives it a worse T​QTQ-cost.
Because the families preserve alternatives, progress need not be
monotonic in either resource. The Gaussian lineage in
, for example, contains descendants that
temporarily worsen Toffoli count or qubit count before reaching a region of lower
T​QTQ-cost. We report the lowest T​QTQ-cost reached across all families at the end
of the search.

I Syndrome decoding for DQI
Consider an optimization problem over a finite field 𝔽q\mathbb{F}_{q}. An
assignment x∈𝔽qnx\in\mathbb{F}_{q}^{n} produces mm linear values B​xBx. Given a set
Fi⊂𝔽qF_{i}\subset\mathbb{F}_{q} of acceptable values for each constraint, let

is to maximize f⁡(x)f(x). This family, known as max-LINSAT, includes linear
constraint-satisfaction problems such as Max-Cut and max-XORSAT, as well as
nearest-codeword problems and polynomial fitting over finite fields. Decoded
quantum interferometry (DQI) is a quantum algorithm that aims to solve these
optimization problems by arranging for constructive interference on assignments satisfying many
constraints and destructive interference on assignments satisfying
fewer [1].

distance dmin≥2​ℓ+1d_{\min}\geq 2\ell+1, a decoder can recover ee uniquely from that syndrome.

This syndrome map defines a [4095,4025,71]212[4095,4025,71]_{2^{12}} Reed–Solomon code.
The 70 twelve-bit syndromes occupy 840 qubits. Assuming the error weight is at most 35, the decoding task is to recover the error from the syndromes.
Decoding proceeds in two stages: first find the positions of the errors, then
recover their values in 𝔽212\mathbb{F}_{2^{12}}. The first stage packages the
unknown set of error positions into a single polynomial. For each nonzero

(27)

the roots of σ\sigma identify exactly the positions at which the error word
is nonzero. The decoder’s first task is therefore to recover this

Reconstructing BM history.
Reversing a round requires the discrepancy that the round used, which the
round computes into a temporary register. Keeping a
twelve-bit history word for every round would raise the qubit count to 2,677.
A replace round leaves σ0=Δ−1\sigma_{0}=\Delta^{-1} by
Equation 34, so the locator determines the round’s

stores it on the history stack before erasing that register.

final degree. Once it has, subsequent discrepancies stay zero and do not
start new runs of retain rounds. Consequently, most inputs need few saved
discrepancies. The discovered circuit allocates only one stack entry,

basis monomials. Beyond error weight 33, some of the syndromes that the recurrence needs have weighted
degree above 150, which the input does not supply. The Feng–Rao baseline reconstructs these

the extended sequence to locate and evaluate the errors [39].
Our reversible implementation of this baseline uses 100 million Toffolis at a peak of
190,000 qubits, for a T​QTQ-cost of
2.0×10132.0\times 10^{13}. The
large qubit count comes from retaining the intermediate states of the recurrence updates until the circuit reverses the computation.
The discovered circuit instead turns locator finding into a null-space problem
for a symmetric matrix AA built directly from the supplied
syndromes. It never stores AA; instead, it computes the effect of multiplying
a vector by AA directly from the syndromes. Repeating this operation produces
a sequence of vectors that must eventually become linearly dependent, and
such a dependence yields the desired null vector. The circuit processes this
sequence incrementally, retaining only a few vectors at a time and grouping
several consecutive vectors when a vector cannot be processed alone. Once
the null vector supplies a locator σ\sigma, the circuit still avoids constructing the
whole evaluator ω\omega or the decoded error word. It scans the curve points in small batches called stripes,
combines the locator and syndromes only for the current stripe, applies those
points’ phase contributions, and clears the temporary data before continuing.
The circuit thus has two stages: a locator walk that never stores the
matrix, and a space-efficient phase scan. The walk freezes on the rare inputs that need
extra work and repairs them at scheduled rounds. Its reversal recomputes most
decisions and stores one bit per round.

Ending and reversing the walk.
For a given input, the walk ends when g0=g1=g2=0g_{0}=g_{1}=g_{2}=0, because no block of depth up
to three is then invertible. The circuit freezes the walk there and records the
round, as the divstep circuit does
(SI II.1). After the last round, it tests which of three
cases holds and routes the corresponding vector into the locator register. If

accumulated vector is the null vector. If 𝒘≠0\boldsymbol{w}\neq 0 and

null vector. An input in none of these cases fails.
After the phase scan described below, the circuit must undo the walk. It
first measures the locator register in the XX basis. The walk built that
register by adding multiples of basis vectors, so the reverse walk can
correct the phase left by the measurement as it retraces the rounds: each
addition becomes a set of controlled-ZZ gates conditioned on the measurement
outcomes, at no Toffoli cost. The reverse walk recomputes most of the
decisions of the forward walk, such as its zero tests, while the vectors they
depend on are present. One decision per round cannot be recomputed in time:
whether the round advanced the walk, which controls an exchange of the two
stored basis vectors. The forward walk stores that decision in one history
qubit per round, 52 in all, and the reverse walk clears them. The reverse walk
uses 52,000 fewer Toffolis than the forward walk.

II.1 Divsteps
Rather than reorganize the binary-gcd constructions above, the search finds a new reversible
prime-field inversion architecture built on
divsteps [15, 53]. In the divstep
recurrence of Equation 6, a small signed counter zz, called the half
delta, replaces the repeated magnitude comparisons in
Equation 55: the sign of zz and the parity of one value alone
determine the next update. We call the choice of update at a step its
decision. Appendix A proves that every decision can
be computed exactly from the registers as they stand after the step. When a decision
is cheap to decode, the circuit decodes it from the updated state. Otherwise,
the circuit stores the decision as a single bit on a fixed-size history stack.
We call the sequence of divsteps for one input a walk.
The point adder uses this inversion twice, once to form the slope λ\lambda
and once to erase it after the coordinate update. Each use runs a forward
walk and a reverse walk, for four walks in total.
Unlike the quotient-based extended Euclidean algorithm (EEA) of
SI II.2, which divides one remainder by the other at
every iteration, a divstep never computes a
multi-bit quotient or adds a multiple of one full register to another.
A divstep walk needs more steps than the quotient-based EEA needs divisions, but each step is
much cheaper. Reversible divsteps were previously
developed over binary fields and polynomial
rings [54, 13]. There, each step
shrinks the polynomial pair by one coefficient, and the freed space can hold
that step’s record. Integer divsteps free no such fixed space, so a stored
history costs additional qubits. To our knowledge, this
is the first reversible divstep inversion circuit over a prime field.
We recall the notation of the main text. The walk state is
(z,f,g,fv,gv)(z,f,g,f_{v},g_{v}), and each step applies one of the three updates in
Equation 6. Two bits label the update: ss records whether
the step swaps the roles of ff and gg, and bb records whether the incoming
gg is odd. To run a step backward, the circuit must know ss and bb, and the
updated state does not hold them explicitly. Cheap tests on a few bits of the
updated state recover ss at every step and bb at about two thirds of the
steps. We call the remaining decisions ambiguous. Each ambiguous
decision has a depth jj, the number of trailing zero bits of the
updated coefficient fv′f_{v}^{\prime}, and we write fv′=2j​qf_{v}^{\prime}=2^{j}q with qq odd. A swap
followed by a run of ambiguous decisions is an excursion, and the depth
counts the steps of the excursion so far, with the swap as step 1. The cost of a
depth-jj decoder grows with jj. The cutoff jstorej_{\mathrm{store}} is the depth from
which the circuit stops decoding: it decodes an ambiguous decision at depth
j<jstorej<j_{\mathrm{store}} and stores one at depth j≥jstorej\geq j_{\mathrm{store}}.
The cutoff jstorej_{\mathrm{store}} trades qubits for Toffolis: a higher cutoff decodes more and stores less. At jstore=0j_{\mathrm{store}}=0, the circuit uses only the cheap tests and
stores every remaining decision, requiring 198 history qubits for the 533-step
schedule and 1,065 qubits in total. The discovered circuit chooses the
intermediate cutoff jstore=5j_{\mathrm{store}}=5: it decodes depths two through four
with the rules given below. Storing only the deeper decisions shrinks the
history stack from 198 to 60 qubits. At the low-qubit
extreme, jstore=9j_{\mathrm{store}}=9 decodes through j=8j=8 and reserves 24 history

Branch decoders.
A forward step computes bb from the parity of gg and uses it to control the
update. After the update, gg no longer holds that parity, so the step is left
with bb in a qubit of its own. Uncomputing bb there would require the
decoder on the forward walk as well. The forward step instead disposes of
bb in one of two ways. If the decision is ambiguous at depth
j≥jstorej\geq j_{\mathrm{store}}, the step pushes bb onto the history stack.
Otherwise, the step removes bb by MBU: it measures bb in the XX basis. The measurement frees the
qubit but leaves a phase that depends on bb and on the measurement outcome.
The reverse walk is the uncomputation of the forward walk. Once the circuit
has used the inverse, it undoes the forward steps in the opposite
order, which restores ww and returns the walk registers to zero. The matching reverse step obtains bb
again, either by popping the stack or by
applying the tests and decoders to the updated state. It applies the
phase correction for the measurement outcome and uses bb to choose which update
to undo. The restored gg then holds bb as its parity, so a CNOT from the low bit of gg clears it.
Decoders therefore appear only in reverse steps.

Early stopping.
A walk terminates when gg reaches zero: at that point f=±1f=\pm 1 and the
inverse can be read from fvf_{v}. Different inputs terminate at different steps,
typically between steps 505 and 530 (Figure 3(b)), but the circuit
runs a fixed schedule of 533 steps. The steps after termination must leave
the state unchanged. Left alone, the recurrence would treat g=0g=0 as an even
value, so it would keep doubling fvf_{v} and incrementing zz until both outgrow
their registers.
The circuit therefore freezes a terminated walk. Each forward step tests
whether g=0g=0. On the first step where the test succeeds, the circuit sets a
one-qubit frozen flag, and from then on the flag disables every update. The
reverse walk must clear the flag at that same step. A frozen state looks
identical at every later step, so the state alone cannot reveal when the walk
froze. The circuit writes the step index into a small register
when it sets the flag. Each reverse step compares the register with its own
index, and a match clears both the flag and the register.
This machinery costs Toffolis at every step: a test that every bit of
gg is zero, and one more control on every update. The test is most expensive in the
early steps, where gg is widest and termination is least likely. The first
498 steps omit the test, the flag, and the flag’s controls. A walk
that terminates within those steps fails. The measured probability is

II.2 Specialized Euclidean construction
This subsection reports a second discovered circuit, at the low-qubit end of
the Toffoli–qubit frontier (Table S3): 843 qubits against 935 for the
divstep circuit, at about five times the Toffoli count. Here the search does
not find a new inversion algorithm. It starts from the space-efficient
Euclidean point adder of Luo et al. [40], which we rebuilt as a
complete circuit, and specializes its schedule for the prime pp. The
schedule is the fixed list of steps, and of bit positions within each step,
that the circuit runs.
Our reconstruction, the baseline below, uses 69.5 million Toffolis and 838 qubits. The discovered
specialization uses 843 qubits while reducing the Toffoli count
to 20.5 million, a factor of 3.43.4. We use the same inputs and outputs, input
distribution, and failure budget as above.

Each iteration of Equation 60 is an integer division. The

The baseline circuit exploits the fact that the remainders rir_{i} shrink as the
coefficients tit_{i} grow. It stores a remainder and a coefficient from
opposite ends of the same register, and stores the succeeding pair
in a second such register. We call values that share a register in this
way packed. Four short counters record where the
four values begin and end.
The circuit processes these packed values by scanning across their possible
bit positions. At each position, it uses the counters to decide whether that
bit belongs to the value currently being processed; we call this check a
counter test. If it does, the circuit
performs the required one-bit arithmetic; otherwise it does nothing. The
fixed circuit must include this test and arithmetic for every position that
any input could require, even though a particular input uses only
a much smaller range of positions.
Each step runs several scans, one each for the remainder update, the coefficient
update, and the rearrangement of the packed values. The path
that the boundary between a remainder and a coefficient traces during an
inversion is the input’s Euclidean walk.
Each use of the inversion performs an in-place division or multiplication. For the slope, a
forward pass replaces ww by its inverse, one multiplication forms the
quotient in an accumulator, an XX-basis measurement erases the old
numerator, and the reverse pass restores ww. The second
inversion runs the same sequence in the opposite order to erase the slope.
Every step consists of in-place reversible operations on the packed registers
and counters, so the reverse pass is the inverse circuit and needs no
stored history. By contrast, the divstep circuit must
recover a decision at every step.
The discovered circuit keeps the baseline’s packed register layout and reduces
the cost of its schedule mainly in three ways. First, it omits scan positions that
inputs rarely use. Second, it removes selected counter tests. Third, it
recompiles the scans of a step together so that they share intermediate
results. The first two changes fail on rare inputs, which count against the
2×10−42\times 10^{-4} failure budget per point addition. The third
is exact.

range with a fitted window: a range chosen separately for each step and fitted to the

Test-free positions.
A fitted window still leaves a counter test at every position inside it, and
a counter test is expensive. In the baseline, a position whose arithmetic is
conditioned on a counter costs about ten Toffolis, several times the cost of
the arithmetic alone. Where every sampled input uses a position at a given
step, the schedule marks the position test-free, and the circuit
performs its arithmetic unconditionally. Counter tests remain at the other
positions inside the window, near the moving boundaries of the values. On an
input that does not use a test-free position, the unconditional arithmetic
produces a wrong result. The two approximations remove different costs. A fitted
window deletes both the test and the arithmetic at the positions outside it.
A test-free position keeps the arithmetic and deletes the test.
Figure S2(c) shows the resulting per-step cost.
Merged scans and measured carries.
The baseline circuit compiles the scans within a step separately, so
neighboring scans repeat some of the same comparisons and compute some of
the same control bits. Compiling the complete step as one operation removes
this repetition; we call this change merged scans. The clearest
instance is the remainder update. The comparison that decides whether a
subtraction applies and the subtraction itself run over the same two
remainders, and the baseline compiles them as two passes. The discovered
circuit merges them into one compare-and-subtract scan whose intermediate
bits serve both operations. It then erases those bits by measurement, which
needs no Toffolis, instead of uncomputing them. The baseline also shifts a
register’s contents, by an amount that depends on the input, as the values
change size. The discovered circuit renumbers the positions instead
of moving the qubits, which costs no gates. In the additions that
remain, a carry that only one position needs is likewise erased by
measurement (measured carries). These changes are
exact.

III Numerical function evaluation
Elementary-function evaluation has been a central problem in numerical
computing since the earliest mathematical software libraries. The routines
conventionally collected in libm, the mathematical-function library
supplied by C and Unix systems, evaluate roots, exponentials, logarithms, and
trigonometric functions by combining range reduction, table lookup,
polynomial approximation, and iterative refinement [57].
These functions also appear throughout quantum algorithms. They determine
controlled rotation angles in quantum linear-systems
algorithms [58, 12], set interaction phases in
real-space Hamiltonian
simulation [59, 60], and enter the amplitudes prepared
for Hamiltonian simulation [4].
These classical techniques cannot simply
be ported into coherent quantum circuits. Data-dependent choices must be
compiled into a fixed gate sequence, and all temporary state must ultimately
be returned to |0⟩\ket{0}. The latter reversibility constraint is particularly
costly for numerical routines because many classical methods proceed through
a long sequence of large, high-precision intermediate values. An ordinary
implementation can overwrite each value and reuse the same storage as soon as
the next value is formed. A reversible implementation must instead retain
enough information to reconstruct the overwritten value, or recompute it when
clearing the circuit. Consequently, composing individually efficient routines
can accumulate many large live registers and may require running the complete
computation backward after its result has been consumed. Iterative Newton-style
methods repeatedly replace one full-precision estimate with another, so their
reversible implementations carry large intermediate registers through every
step [61]. Floating-point representations add exponent bits
to every such register to track a wide range of
magnitudes [62]. The approximation, fixed-point
representation, and uncomputation schedule therefore become inseparable parts
of circuit design [12].
We consider three numerical subroutines:
Harrow–Hassidim–Lloyd (HHL) rotation-angle evaluation (arcsin\arcsin),
Coulomb-potential evaluation (1/‖x‖21/\sqrt{\|x\|^{2}}), and Gaussian
evaluation (e−x2e^{-x^{2}}) [58, 59, 2]. Each
implements an additive fixed-point map

For arbitrary, unstructured table data, QROM has no pattern to exploit: in the

system with exact spin symmetries and repeated orbital environments, so many
coefficients are equal and many Pauli operators are related. We therefore
choose the table to suit the circuits. Two degrees of

coefficients and Pauli operators leaves

realize the same rounded distribution. The preprocessing uses the first freedom

alias words into repeated patterns, shortening QROM.
Frame-block Select.
Many Pauli operators in this Hamiltonian are related by fixed Clifford
transformations, which we call frames. Suppose, for example, that two commuting frames
generate four related Pauli operators from one representative. Instead of
selecting four operators independently, the circuit selects the representative
once and uses two bits of the address (the selected row index) to
control the two frames. More
generally, kk such bits can identify up to 2k2^{k} operators in a block. The
circuit pays for one block representative plus its controlled
frames, rather than every Pauli operator separately.
The circuit applies a frame by conjugation. It applies σ†\sigma^{\dagger} to the system
register under a control, then the representative PP, then σ\sigma under the same control.
The result is σ​P​σ†\sigma P\sigma^{\dagger} when the control is set and PP
otherwise. Each frame is applied once for the whole table rather than once per
block. Blocks that use the same frames are contiguous, so a few comparisons of
the address with fixed boundaries determine which frames are active.
These relations have a physical origin: the model contains two
equivalent spin channels, two similar iron sites, and corresponding orbitals
on repeated parts of the cluster. These repetitions create Pauli operators that
are related by a fixed transformation. Each frame is a permutation or change of basis of the
spin-orbitals. The Jordan–Wigner mapping turns it into a fixed Clifford
transformation of the 40 system qubits.
Two of the frames used here come from exact spin symmetries of the Hamiltonian.
Because the model treats the spin-up and spin-down channels
identically, σα​β\sigma_{\alpha\beta} exchanges the spin-up and spin-down modes
of every spatial orbital. Spin-rotation symmetry produces a second pairing
after the Jordan–Wigner mapping: σX​Y\sigma_{XY} exchanges the XX and
YY factors and adjusts the accompanying ZZ strings required by that
mapping. Both transformations preserve the corresponding coefficient
magnitudes.
The other five frames come from parts of the cluster that resemble each
other; unlike the two spin frames, they are not symmetries of the full
Hamiltonian. The frame σFe\sigma_{\mathrm{Fe}} is the approximate left–right
reflection of the cluster, which exchanges the two iron centers and their
surrounding orbitals. The frame σFe′\sigma^{\prime}_{\mathrm{Fe}} combines this
reflection with several local orbital swaps and matches Pauli operators that
the bare reflection misses. The frames σthio\sigma_{\mathrm{thio}},
σ3​d\sigma_{3d}, and σμ​S\sigma_{\mu\mathrm{S}} exchange corresponding orbitals on
the terminal thiolates, the iron 3​d3d shells, and the bridging sulfur atoms.
These sites have similar but not identical electronic environments: the
permutation often maps one term’s Pauli operator onto another’s, but the
coefficients differ. Only the Pauli relation Pℓ′=σ​Pℓ​σ†P_{\ell^{\prime}}=\sigma P_{\ell}\sigma^{\dagger} must hold exactly; wℓ′w_{\ell^{\prime}}
and wℓw_{\ell} remain independent entries in the alias table.

alternate A,B,A,BA,B,A,B; ours prefers A,A,B,BA,A,B,B. Rows 1–2 then share a threshold, an alternate term, and hence an
alias word, as do rows 3–4.

terms can supply the missing weight of many lighter rows. Because the pairing only redistributes each term’s weight among
buckets, it preserves the rounded distribution and creates long

identical alias words.

V Nonabelian lattice-gauge simulation
In Hamiltonian lattice gauge theory, space is replaced by a grid. A gauge-field
configuration assigns a group element Ui​(𝐱)U_{i}(\mathbf{x}) to each directed edge,
or link, from site 𝐱\mathbf{x} in direction ii. This element describes how the
gauge field transports a state between neighboring sites; traversing the link
backward contributes its inverse Ui​(𝐱)−1U_{i}(\mathbf{x})^{-1}. Multiplying the links
around a closed path therefore describes the net transport along
that loop. Although this product depends on an arbitrary convention at each site (the
gauge), the real part of its matrix trace does not, and these loop traces
form the magnetic energy [73]. Because the gauge group is
nonabelian, its elements need not commute, so the links must be multiplied in
the order in which the path traverses them.
We consider the group-register formulation of Hamiltonian lattice gauge
theory [73], in which a register holds the group element of
each link. The Hamiltonian separates into an
electric (kinetic) term HEH_{E} and a magnetic (potential) term HBH_{B}. A Trotter
step evolves these terms separately. Here we implement the magnetic evolution
e−i​Δ​t​HBe^{-i\Delta tH_{B}} for the improved Hamiltonian of
Carena et al. [74]. The smallest loop contributing to HBH_{B} goes around
one square face of the lattice and is called a plaquette; the standard
magnetic term sums a trace over these four-link loops. The improved
Hamiltonian adds weighted 2×12\times 1 rectangles, which cancel the leading
discretization error. Thus the
magnetic evolution requires the same basic operation at many locations:
follow a short closed path, multiply its links in order, extract a
trace, and add the weighted result to the phase. The
compilation task studied here is one application of the magnetic evolution to
the whole lattice, which we call the magnetic layer.

Specialized running-product representation.
Repeatedly multiplying the running product WW by links dominates the cost,
so the circuit uses a representation tailored to the restricted update
W←W​gW\leftarrow Wg rather than to arbitrary group multiplication. Multiplication in
the original normal form is costly in part because XX has a complicated
conjugation action. However, the normal form can use any element of the
u=1u=1 coset in place of XX. We replace XX by Xo=C​E​XX_{o}=CEX. Because XoX_{o} differs from XX only by
factors of CC and EE, rewriting a link in terms of XoX_{o} changes only
p,q,rp,q,r. XoX_{o} is the unique such element that satisfies

Compare these relations with Equation 79: the V,XoV,X_{o} part now
closes on itself instead of spilling corrections into the other coordinates.

the links and for WW. Each link is recoded as

The 192 links are recoded once

remains in a compact nine-qubit encoding; storing every link one-hot would cost

product, so we can afford to store its three-valued coordinates P~\widetilde{P}, QQ,
and RR one-hot (three qubits, exactly one set), increasing the size of WW from nine to twelve qubits. Adding one
modulo three then becomes a cyclic permutation of three qubits, while negation
becomes a single swap. Controlled additions and the fixed transformations
above can therefore use controlled qubit permutations rather than arithmetic
on the two-qubit encoding. Together, these
representation choices reduce each update of WW from 146
Toffolis in the baseline’s general multiplication circuit to 35 Toffolis.
Multiplying by an inverse link g−1g^{-1} costs the same, so the circuit needs
no separate link inversion.

Reusing loop products.
The baseline constructs each loop product from the identity and then reverses
the construction. Neighboring loops, however, often share a sequence of
factors. The discovered circuit therefore retains WW after one trace
evaluation and edits it into the product needed for the next, reusing the
shared factors instead of rebuilding them.
More loops share factors than first appears, because the
real trace is invariant under cyclic rotation and inversion:
f(h1h2⋯hn)=f(h2⋯hnh1)=f((h1h2⋯hn)−1).f(h_{1}h_{2}\cdots h_{n})=f(h_{2}\cdots h_{n}h_{1})=f((h_{1}h_{2}\cdots h_{n})^{-1}).
(86)
The first equality is cyclicity of the matrix trace; the second follows
because these matrices are unitary and ff takes the real part.
For example, to change a​b​c​d​eabcde into a​b​c​x​yabcxy, the circuit right-multiplies by
e−1e^{-1} and d−1d^{-1} to cancel the old suffix, then appends xx and yy,
retaining the common prefix a​b​cabc. Inverting WW, which costs 21 Toffolis, makes the other end of the
product available for the same operation. Cyclic rotations and inversion also
give several equivalent ways to write each loop, which we call its
representatives, all with the same value of ff. As Figure S5(a) illustrates, a good
choice can expose a longer segment shared with the next loop. A classical dynamic program chooses the representatives and the order in
which the loops are evaluated, minimizing the
cost of transforming WW between consecutive representatives. The chosen schedule uses 3,136 link
multiplications and 480 inversions of WW for the 576 loops, about 5.4
multiplications per loop. By comparison, building and reversing each loop separately takes 6 multiplications
for a plaquette and 10 for a rectangle.
