# 本地套版、備註與 Canva 匯入

在使用者回傳投影片或已授權助手製圖後閱讀。製作順序：回傳或生成素材與已確認稿件 → 本地 PPTX 完成 → 本地檢查 → 匯入 Canva → 檢查匯入結果。

## 本地範本

預設使用隨 skill 附的 [範本.pptx](../assets/template.pptx)。使用者當次指定新範本時，以新範本為準。

已檢查的範本是兩頁、16:9（18288000 × 10287000 EMU）：

- 第 1 頁：白底、左側「本週大綱」、右側四個條列標題佔位，左下品牌貓頭鷹，備註已有開場與宣傳文字。
- 第 2 頁：白底與左下貓頭鷹，右側大圖是長債 5.34% 的舊示例，上方另一個獨立圖片寫「長債急跌，非農爆冷卻成利多？」。備註有「逐字稿」佔位。

保留白底、貓頭鷹原始圖片、比例與位置。舊主圖、舊標題與「逐字稿」佔位必須替換。週報第 1 頁備註中的開場與宣傳是使用者指定的固定原文，完整保留，不改成選題介紹；原文另存 [weekly-opening.txt](../assets/weekly-opening.txt)。這是講者備註，不把宣傳段貼到大綱畫面。新範本或使用者明確改稿時依新指示。

範本的圖片是圖形填滿（`a:blipFill`），不全是 `p:pic`。不要用「圖片物件數為零」推論沒有圖片。需要修改時按位置、圖形名稱／描述和關聯辨識內容，不全域替換共享資產。

已檢查的內容頁座標供定位，實作前仍讀取實際範本：

|---|---:|---:|---:|---:|

## 檢查輸入與逐頁對照

1. 找出最新已確認稿件及本次素材。確認素材是逐頁圖片、PDF、PPTX、右側主圖，或已完成套版的整頁。
2. 檢查總頁數、順序、方向和缺頁。建立 Slide 編號 → 素材頁／檔名 → 口白 → 週報主題的對照。
3. 稿件與素材數量不符或順序無法判定時，先列出具體差異；不要猜著貼、重複素材補頁或自行重寫已確認口白。
4. PDF 按原頁順序轉成清楚的獨立頁面素材；PPTX 若主要是完成的主圖，也可按頁取得視覺素材。保留來源，不改使用者已完成圖的內容。

## 本地組裝

使用簡報技能與當下可用的簡報工具處理本地 PPTX。依其要求讀取相關實作文件，在副本上重用範本頁面，保留來源和品牌資產，不覆寫原範本或使用者原稿。

內容模式以稿件為準；週報選用主題影片版型仍保留週報大綱與完整外部分類標題，不能套用下方單題片的無標題規則。

週報：第一頁套用大綱頁，依本集主題調整條列，不能保留「標題」佔位。內容頁複用第 2 頁，同一主題使用同一分類標題；進入下一主題才換標題，不給每頁各取一個標題。

主題影片：只有第一頁有整片大標題。第一頁可沿用內容頁構圖放大標題與首張素材，後續內容頁移除舊示例標題物件，保留主圖區與品牌。不要強加「本週大綱」或加一張額外封面導致原稿與素材錯位。

標題優先用可編輯文字，依範本風格與區域安排。原上方標題是圖片，不能假設改文字就會替換它。若回傳主圖已含同一標題，避免重複加字；若與本片標題規則衝突且需要改動使用者原圖，先說明具體衝突。

逐頁將回傳素材放入主圖區，不重設計內容。若使用者回傳的是已完整套好的整頁，先判定是否可沿用其頁面，只補逐字稿備註，避免將整頁縮進右側框造成雙重品牌和過小內容。

將每頁完整已確認口白寫入 PowerPoint 的 speaker notes／備註。逐字稿與講者備註只放口白，不追加資料來源、網址或製作資訊；資料來源另存研究文件。逐字稿不覆蓋到畫面上、不截短、不只另附文字檔。

## 本地驗證

- 儲存後重新讀回 PPTX，核對素材、稿件和頁數／順序一一對應，尤其封面與大綱是否造成偏移。
- 檢查每頁備註完整對上該頁口白；週報第 1 頁為固定開場，其他頁沒有示例口白或「逐字稿」佔位。
- 渲染並查看全套頁面，檢查貓頭鷹、圖片品質與裁切、圖表標籤、標題規則、字體及文字溢出。文字讀回不替代視覺檢查。
- 輸出可直接使用的本地完成 PPTX，供使用者下載及作為 Canva 匯入來源。只有真正完成本地組裝與備註才能稱為本地套版完成。

## 匯入 Canva

完成本地 PPTX 後，再將這份檔案匯入為新的 Canva 簡報。舊流程的 Brand Template `EAHWQZgt3Kk` 不再是預設套版入口；不在 Canva 重新生成或重新套品牌模板。

先檢查當下 Canva 工具的支援與參數。若匯入工具支援本地 `design_file`，傳入完成 PPTX 的絕對路徑及 presentation 類型，與 `url` 擇一。如果需本地檔案上傳，使用官方檔案上傳能力；單純取得上傳資源 ID 不代表已完成設計匯入。不要為匯入而把私人稿件發布成公開 URL。

匯入完成後取得正式設計連結，讀回頁數、頁面和 Presenter Notes，並檢查匯入後的畫面。不要假定 PPTX 備註一定被 Canva 保留。

若 Canva 沒保留備註，先確認連接器是否支援寫入；只有讀取工具時，可在既有授權範圍內使用瀏覽器編輯器補入並等待儲存，再用連接器讀回。工具與 UI 都無法完成時，明確告知「本地 PPTX 已含逐頁備註，但 Canva 的備註未完整保留」，附逐頁備註文字供貼入，不宣稱已在 Canva 完成備註。

只有建立並儲存成功才交付正式 Canva 連結。若 Canva 匯入不可用，先交付已完成的本地 PPTX 和具體限制，不把檔案上傳、空白草稿或生成預覽稱為完成的 Canva 簡報。修改或覆寫既有 Canva 設計，需依當次使用者授權處理。

### 匯入版面失真時

本次實作曾遇到 Canva 匯入圖形圖片填滿後，貓頭鷹縮小、字型替換、標題與標籤失真。不要把匯入成功視為版面正確，也不要無差別重畫品牌。

若需要穩定保持已確認畫面，可保留本地可編輯完成版，另輸出 Canva 匯入版：將本地渲染的每張完整頁面以一張高清圖片鋪滿整頁，仍逐頁加入完整口白備註，再匯入。這裡用的是「完整頁面」，不能只把右側主圖拉滿。向使用者交代 Canva 畫面文字會與圖片合在一起，備註仍可編輯；若使用者要求畫面元素可編輯，則修正原生物件而非直接採用整頁圖片。

重新匯入後逐頁檢查全套頁面，尤其品牌大小、首張標題、圖表細字及本地補入的標籤。將正式 design ID、連結、頁數、匯入方式與備註核對結果記入專案交付紀錄，避免把測試設計當成正式版本。不要刪除舊設計，除非使用者授權。

### 交付後只改口白或移除來源

1. 先保存正式 Canva 當下備註並與本地稿比較。使用者可能正在直接改稿，以其較新人工編輯為準；只合併指定頁及必要銜接，不能全量回寫舊備註。維持 Slide 編號對照，將合併後口白同步到本地完成版與 Canva 匯入版。候選句與已套用版本分清楚。
2. 在正式 Canva 設計原地編輯，保留原連結及畫面。當下沒有備註寫入 API 時，使用編輯器的備註欄。
3. Canva 縮圖列表可能虛擬化；點擊未顯示縮圖曾跳到錯頁。較可靠的當次做法是點底部頁碼，使用「前往頁面」輸入頁碼，核對備註面板的「第 N 頁」後填入。這些 UI 名稱可能變動，實作時讀取當下狀態，不固定索引或盲點座標。
4. 儲存後讀回修改頁的本地及 Canva 備註，與合併後最新版口白逐字比較。初次全套交付或全稿修改時才核對全套。僅檢查有字或沒有網址不足以證明版本同步。來源與網址留在研究文件；畫面上的來源註腳是否修改，依使用者指定範圍處理。
5. 只改備註時，確認頁數、圖片與畫面文字維持原樣；不重新生成圖片。更新交付核對紀錄，保留必要的修改前副本。

## 備註修改時保留原生圖表

本次在既有 PPTX 匯入簡報工具後重匯出，曾丟失圖表的來源工作簿關聯，導致驗證失敗。不能為了通過檢查憑空補造工作簿或公式出處。只改備註時，優先使用保留現有套件的修改方式；若工具會重建全檔，可先用工具產生合法備註 XML，再將指定 notesSlide XML 合併到原 PPTX 副本。只有在關聯與版面相容時才替換，保留圖表、嵌入工作簿、媒體及其關聯。若需新增備註或改動版型，不能假設只換一個 XML 即可。

## 檢查的停止條件

首次交付做一次完整本地與 Canva 核對。局部修正核對修改頁及可能受影響的部分，不反覆截取全套。使用者正在操控 Canva 時，先避免爭用目前頁面；必要操作以已讀取的頁碼為準，不能假定還停在上一頁。使用者說「看過了、可以了、不要再檢查」，立即停止檢查、截圖與操作，簡短確認採用目前版本。後續新修改才重新核對相關部分。
